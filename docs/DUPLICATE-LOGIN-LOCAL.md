# ยืนยันการล็อกอินซ้ำ: EIS-DOCS / Supplies

เปิดใช้งานบน local `dev-eis.nmu.ac.th` แยกหนึ่งเซสชันต่อบัญชีต่อระบบ เปิดหลายแท็บด้วย cookie ของเซสชันเดียวกันยังใช้งานได้ตามปกติ

## พฤติกรรม

1. ตรวจรหัสผ่านหรือสิทธิ์ SSO/สวมสิทธิ์ให้สำเร็จก่อนตรวจว่ามีเซสชันเดิมหรือไม่
2. หากมีเซสชันเดิม แสดง **ยืนยันเข้าสู่ระบบแทนที่เซสชันเดิม** และ **ยกเลิก** โดยยังไม่ให้เซสชันใหม่เข้าใช้
3. ยกเลิกแล้วเซสชันเดิมยังใช้ได้ ยืนยันแล้วให้เซสชันใหม่เข้าใช้ และเพิกถอนเซสชันเดิมเฉพาะระบบนั้น
4. คำยืนยันผูกกับ PHP session และ CSRF มีอายุ 2 นาที ไม่เก็บรหัสผ่านในฟอร์มหรือ pending proof ตรวจบัญชีอีกครั้งก่อนยืนยัน
5. หากมีคนอื่นล็อกอินแทรกระหว่างรอยืนยัน ต้องยืนยันใหม่ ไม่ใช้คำยืนยันเก่าทับเซสชันที่เพิ่งเข้า

EIS-DOCS แสดงคำยืนยันในหน้า Login หรือหน้าสวมสิทธิ์ Supplies แสดงที่ `/supplies/access/confirm-login.php` กรณี NMU_permission ล็อกอินผ่าน iframe/API จะคืน `duplicate_login` และเก็บคำขอไว้ จากนั้นแสดงหน้ายืนยันเมื่อเปิด Supplies การเปิดหน้าซ้ำไม่ใช้ query parameter `override=1` เพื่อข้ามคำยืนยัน

## การเพิกถอน

ทะเบียนเซสชันอยู่ที่ `storage/presence/logins/` ใช้ file lock ครอบการตรวจและจองเซสชันเพื่อรองรับการล็อกอินพร้อมกัน ตรวจทะเบียนทุกคำขอที่ผ่านจุดตรวจ session ของ EIS-DOCS/Supplies เซสชันเดิมจึงถูกปฏิเสธที่ PHP/API แม้ปิด JavaScript หรือ WebSocket

เมื่อ service ได้รับการเชื่อมต่อใหม่ จะปิด connection ของเซสชันที่ถูกแทนที่ก่อนเปิดรอบใหม่ ถ้าเซสชันใหม่ยังไม่เชื่อมต่อ service จะตรวจเครื่องหมายเพิกถอนในรอบ heartbeat ภายใน 10 วินาที บันทึกเหตุผล `login_replaced` และเวลาเพิกถอนจริง หน้าเว็บแจ้งว่า **เซสชันนี้ถูกแทนที่จากการเข้าสู่ระบบใหม่** แล้วกลับหน้าเข้าสู่ระบบ

รีโหลดหน้าเว็บเพื่อใช้ client เวอร์ชันใหม่ การป้องกันฝั่ง PHP ทำงานกับเซสชันเดิมด้วย ทะเบียนของเซสชันที่เข้าระบบก่อนติดตั้งจะเริ่มบันทึกเมื่อมีคำขอครั้งถัดไป

การตรวจล็อกอินซ้ำใช้เซสชันที่ยังไม่หมดอายุ ไม่จำเป็นต้องมีแท็บออนไลน์อยู่ในขณะนั้น ออกจากระบบหรือหมดอายุแล้วเข้าสู่ระบบใหม่ได้ตามปกติ อายุเซสชัน Docs ใช้ `session.gc_maxlifetime` และ Supplies ใช้ idle timeout เดิม 2 ชั่วโมง การต่ออายุ Presence แบบ background ไม่ยืด idle ของ Supplies

## ตรวจสอบ

```powershell
php -n D:/EIS-DOCS/app/services/presence/test-single-login.php
npm.cmd test --prefix D:/EIS-DOCS/app/services/presence
node D:/EIS-DOCS/app/services/presence/integration-local.js
```

PHP test ใช้ข้อมูลบัญชีและ SQL fixtures ในพื้นที่ชั่วคราว จึงต้องใช้ `-n` เพื่อไม่โหลด SQL driver จริง Integration test ใช้ PHP session จำลองและทะเบียนบัญชีรหัสสุ่มสำหรับการทดสอบกับ IIS จริง พร้อม service แยกบนพอร์ต 4004 แล้วลบเฉพาะไฟล์ที่สร้างขึ้นเมื่อจบการทดสอบ

การนำขึ้นระบบร่วมต้องย้ายทะเบียนไปฐานข้อมูล/ที่เก็บร่วมและจัดการ service lifecycle ก่อนใช้หลายเครื่อง รุ่นนี้ยังไม่เปลี่ยนนโยบายของโดเมน production
