# กล่องงานสนทนา: ตอบย้อนหลังและปิดงาน

Admin เปิด https://dev-eis.nmu.ac.th/eis-docs/docMain/message-inbox.php หรือกด **กล่องงาน** จากหน้า User Online

## ผู้ใช้แจ้งเรื่องเมื่อ Admin ออฟไลน์

กดปุ่มสนทนา แล้วเลือก **แจ้งเรื่องถึงทีมผู้ดูแล** พิมพ์เรื่องและแนบรูปได้ ข้อความถูกบันทึกก่อนแจ้งว่าสำเร็จ ไม่ต้องมี Admin ออนไลน์ในขณะนั้น เมื่อ Admin กลับมา เรื่องอยู่ในหน้ากล่องงาน เมื่อผู้ใช้กลับมาเชื่อมต่อ จะได้รับคำตอบย้อนหลัง

งานทีมเปิดให้ Admin ของ EIS-DOCS ที่มีสิทธิ์ตรวจและรับช่วงได้ ผู้ใช้เห็นเฉพาะเรื่องของบัญชีและระบบตนเอง ส่วนแชทส่วนตัวสองคนเดิมอยู่ในกล่องงานของ Admin เจ้าของบทสนทนาเท่านั้น ไม่เปิดให้อีก Admin ดูหรือรับช่วง

## สถานะ

| สถานะ | ความหมาย |
|---|---|
| รอตอบ | มีข้อความผู้ใช้ที่ยังต้องดำเนินการ |
| กำลังดำเนินการ | Admin รับงาน หรือขอภาพหน้าจอ |
| ตอบแล้ว / รอผู้ใช้ | Admin ส่งคำตอบแล้ว แต่ยังไม่ได้ปิดงาน |
| ปิดงาน | Admin ระบุสรุปและปิดงานแล้ว |

การเปิดอ่านไม่ถือว่าตอบหรือปิดงาน การขอภาพหน้าจอไม่ถือว่าแก้ไขเสร็จ ผู้ใช้ส่งเพิ่มหลังปิดงาน ระบบเปิดงานกลับเป็นรอตอบ พร้อมเก็บเหตุการณ์เปิดกลับและสรุปเดิม

## Admin ตอบและปิดงาน

1. ดูการ์ดจำนวนงาน กรองสถานะ ค้นหาชื่อ/หัวข้อ/เลขงาน หรือเลือกเฉพาะงานที่รับผิดชอบ
2. เลือกเรื่องเพื่อดูข้อความและรูปย้อนหลัง โหลดประวัติเก่าได้ครั้งละ 30 ข้อความ
3. **รับงาน** เพื่อระบุผู้รับผิดชอบ ถ้ามี Admin คนอื่นรับไว้ ให้เลือก **รับช่วงงาน** ก่อนตอบ งานส่วนตัวเดิมไม่ให้รับช่วงโดย Admin อื่น
4. พิมพ์คำตอบแล้วส่ง หรือเลือก **ตอบแล้วปิดงาน** เพื่อใช้คำตอบเป็นสรุปในครั้งเดียว
5. กรณีตอบแล้วก่อนหน้า ใช้ช่อง **สรุปการแก้ไขเพื่อปิดงาน** แล้วกดปิดงาน ระบบไม่ให้ปิดก่อนตอบข้อความล่าสุดของผู้ใช้
6. เลือก **ปิดงาน / ดูย้อนหลัง** เพื่อดูคำตอบ สรุป ผู้ปิดงาน วันเวลา และประวัติการดำเนินการ เปิดงานใหม่ได้เมื่อจำเป็น

รับงาน/รับช่วง/ปิดงานตรวจ version ของข้อมูล ป้องกัน Admin สองคนแก้พร้อมกันแล้วทับสถานะกัน งานที่ Admin คนอื่นรับผิดชอบไม่ให้ตอบจนกว่าจะรับช่วงอย่างชัดเจน

## ตอบหลายผู้ใช้

เลือก checkbox ของงานที่ตอบได้ 1–10 งาน พิมพ์คำตอบเดียวกัน กด **ตรวจรายการผู้รับ** แล้ว **ยืนยันส่ง** แต่ละคำตอบส่งแยกห้อง ผู้ใช้ไม่เห็นข้อความหรือรายชื่อผู้รับอื่น แสดงผลสำเร็จ/ล้มเหลวแยกงาน ไม่ปิดงานอัตโนมัติจากการตอบหลายงาน หากงานเปลี่ยนสถานะหรือมีคนรับงานก่อนส่ง งานนั้นจะถูกปฏิเสธและแสดงเหตุผล

ถ้า connection ขาดระหว่างส่งและไม่รับ acknowledgement ให้ตรวจประวัติก่อนส่งซ้ำ เพราะข้อความอาจบันทึกแล้ว แม้ฝั่ง Admin ยังไม่เห็นยืนยัน

## การเก็บข้อมูลและอัปเกรด

เก็บใน private `storage/presence/chat.json` ชุดเดียวกับแชทเดิม งานทีมและงานส่วนตัวที่ติดตามเก็บข้อความเต็ม แยกจากข้อจำกัดห้องรวม 500 ข้อความ/ประมาณ 16 MB/30 วัน ไม่ลบประวัติงานอัตโนมัติ ปิดงานแล้วก็ยังอยู่สำหรับดูย้อนหลัง จำกัดไฟล์รวม 128 MB สำหรับการเพิ่มข้อความ เมื่อถึงขีดจำกัดจะไม่รับข้อความใหม่และแจ้งข้อผิดพลาด ต้องวางแผน backup/archiving ตามการใช้งานจริง

ก่อนนำขึ้น production หยุด Node และ backup chat.json แล้วติดตั้งโค้ดใหม่ Node จะย้ายข้อความส่วนตัวที่ยังมีอยู่เข้าโครงสร้างงานโดยเก็บ read state และสิทธิ์สองคนเดิม ข้อความที่เคยหมดอายุก่อนอัปเกรดไม่สามารถนำกลับมาได้ ห้ามนำ chat.json หรือ backup จาก dev ไป production

local มี backup ก่อนอัปเกรดใน private storage และตรวจ migration จากสำเนาข้อมูลจริงแล้ว

## ไฟล์ที่เพิ่ม/ปรับสำหรับ production

EIS-DOCS:

```text
app/src/Presence.php
app/public/assets/js/presence-chat.js
app/public/docMain/user-online.php
app/public/docMain/user-online.js
app/public/docMain/message-inbox.php
app/public/docMain/message-inbox.js
app/public/docMain/message-inbox.css
```

Supplies:

```text
conf/presence/Presence.php
assets/js/presence-chat.js
```

Node:

```text
server.js
chat.js
```

ใช้ config, secret, storage และ reverse proxy เดิม ไม่มีการเปลี่ยน schema SQL การติดตั้ง production ยังต้องทำบนเครื่องจริง ชุด release รวมไฟล์ข้างต้นและคู่มือนี้แล้ว

## การตรวจ

ตรวจ Node unit tests, WebSocket จริงบน service แยก, IIS สิทธิ์หน้า Admin/ผู้ใช้/สวมสิทธิ์ และ Chrome UI: การฝากเรื่องขณะไม่มี Admin, ตอบและปิดย้อนหลัง, ผู้ใช้กลับมาอ่าน, เปิดงานกลับ, รับช่วง/version conflict, แยกสิทธิ์ private/team, migration, pagination และตอบหลายงาน ผ่านแล้ว
